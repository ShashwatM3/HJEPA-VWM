## Executive diagnosis

Run 052 is not failing because of optimizer instability, NaNs, an inactive reconstruction path, or
a W&B reading mistake. It is doing exactly what its zero-regularizer objective permits: it is
learning a very strong present reconstruction while allowing the bottleneck representation to remain
weakly spread, strongly video-independent, and correlated/low-rank.

The short version:

- `L_recon_present` is excellent: `1.0127 -> 0.2930` by diagnostic step 14500.
- The representation is collapsed by this project's present-only reading cycle:
  `c_std_mean=0.2948`, `c_cross_video_cosine=0.9055`, `c_effective_rank=13.37`.
- The run has no active geometry pressure: `lambda_var=0`, `lambda_sigreg=0`, `lambda_cov=0`,
  `lambda_slot=0`.
- The high-rank runs being compared against all had active geometry pressure, usually
  `lambda_var=0.5` plus `lambda_sigreg>=5`, and the best ones also had covariance pressure.
- The sharpened bottleneck attention is doing something: attention entropy falls to `0.5518`.
  But sharp/selective attention is not the same as video-specific, high-rank, decorrelated `c_t`.
- The apparent "rank goes down" shape is partly a new-metric interpretation issue: the sharp-slot
  code starts with input-independent orthogonal slot identities, so pooled `c_effective_rank` is
  artificially high at step 0 while `c_std_mean=0` and `c_cross_video_cosine=1`. As training
  replaces that artificial slot basis with reconstruction-useful content, rank falls toward the
  low-dimensional/shared-content solution that the objective allows.

Final verdict: **Collapsed rep**. This is strong evidence against the hypothesis "sharpened slots
alone can replace variance/SIGReg/covariance regularization."

## Code-path audit

### Present-only mode is doing what it says

In `train.train_step`, when `present_recon_only` is true:

```text
abstract, detailed = _present_forward(...)
flow_loss = 0
target_clip = None
```

The future branch is skipped. `F_c` is not trained. The only active loss terms are the non-prediction
regularizers whose lambdas are nonzero, plus present reconstruction. For run 052 the active gradient
is effectively:

```text
loss = 0.05 * recon_scale * reconstruction_loss(decoder(c_t), e_t)
```

`variance_floor`, `covariance_floor`, `slot_diversity_loss`, and `sigreg_loss` are still computed
for logging, but their weights are all zero in this run. Their logged values are warnings, not
training forces.

### The bottleneck starts with slot identity, not video content

The current sharpened bottleneck has:

- orthogonal query slots;
- a zero-initialized attention output projection;
- a zero-initialized output MLP residual;
- final LayerNorm.

The test `test_bottleneck_starts_as_normalized_slot_identities` verifies that at initialization the
bottleneck output is the normalized learned slot identities and is independent of `detailed`.

That matters for the rank graph. At step 0 in run 052:

```text
c_effective_rank = 30.99
c_slot_diversity_rank_centered = 30.99
c_std_mean = 0.0000
c_cross_video_cosine = 1.0000
```

This is not a healthy representation. It is the same slot basis repeated for every video. The pooled
rank metric sees different slots, but Q2 shows there is no video-specific variation at all.

As training proceeds, the representation becomes slightly video-dependent (`std` rises from 0 to
about 0.4 early, then falls to `0.2948` by step 14500), but it does so through a low-dimensional,
highly shared direction. That is why:

- `c_effective_rank` falls from the artificial slot-identity value `30.99` to `13.37`;
- `c_cross_video_cosine` remains very high at `0.9055`;
- `L_cov` rises to `30.32`;
- centered slot rank falls to `9.33`.

### The decoder can reconstruct a shared template

The fixed-position decoder does not have learned output-token content queries, and the tests enforce
that zero latent cannot emit position-specific content by itself. That was the right fix for the old
decoder loophole.

However, a nonzero but mostly shared `c_t` can still drive a nonzero shared output through fixed
position queries. That output can be a strong average/template-like reconstruction across videos.
This is enough to reduce the cosine reconstruction loss substantially, especially because V-JEPA
features contain shared spatial/temporal structure. It is not enough to prove that `c_t` carries
video-specific detail.

Run 052's metrics match this degeneracy exactly:

```text
L_recon_present gets very low
but c_cross_video_cosine stays high
and c_std_mean stays low
and L_cov gets worse
```

### Attention selectivity is not the missing ingredient by itself

The sharp attention change did reduce attention entropy:

```text
c_attn_entropy: 0.7551 @ step 0 -> 0.5401 @ step 14500
```

This is lower than many earlier runs. So the failure is not simply "attention is uniform." The more
precise statement is:

```text
The bottleneck can attend sharply, but the reconstruction-only objective does not force the sharp
reads to be spread across videos, decorrelated across feature dimensions, or high-rank.
```

## Hypotheses tested

### H1: The run is unstable or corrupted

Prediction: if this were true, there would be grad skips, NaNs, AGC clipping, high grad norms, or a
late metric cliff.

Result: falsified. `grad_skipped=0`, `grad_has_nan=0`, `instability_warn=0`, `agc_B_clipped=0`,
`agc_D_clipped=0`, and grad norms are tiny. The local focused tests also pass.

### H2: The run is being read with the wrong prediction gates

Prediction: if this were accidentally a full prediction run, `prediction_active=1`, `L_flow>0`, or
`L_recon_pred>0`.

Result: falsified. `present_recon_only=1`, `prediction_active=0`, `L_flow=0`, and
`L_recon_pred=0`. Copy/batch-mean metrics should not be used for this run.

### H3: It just needs more steps

Prediction: if this were a slow-start version of the high-rank runs, by step 8000 it would at least
be trending toward their geometry: rising rank, rising std, falling cosine, falling `L_cov`.

Result: unlikely. At step 8000, the strong present-only geometry runs were already at:

- rank `77.9` to `138.9` for the best SIGReg/covariance configs;
- std around `0.96-0.98`;
- cross-video cosine around `0.07-0.09`;
- low and falling `L_cov`.

Run 052 is moving the other way after step 5500 and continues degrading after the earlier live
snapshot:

- rank `22.04 -> 13.37`;
- std `0.4085 -> 0.2948`;
- cosine `0.8161 -> 0.9055`;
- `L_cov` `18.95 -> 30.32`.

The final trajectory does not resemble the high-rank runs at the same training age.

### H4: The sharpened bottleneck architecture is broken

Prediction: if the architecture were locally broken, tests around sharp attention, gradient flow,
decoder contracts, or present-only routing would fail; attention might also remain uniform.

Result: not supported. The focused tests pass and attention entropy falls strongly. The architecture
did not deliver the desired representation without regularization, but the local contracts are not
obviously broken.

### H5: The zero-regularizer objective allows a reconstruction-template collapse

Prediction: reconstruction improves while Q2/Q3 geometry stays bad; `L_var` remains high because
variance is weak; `L_cov` rises because dimensions are correlated; high-rank runs differ by active
geometry losses.

Result: strongly supported. This is the best explanation for the observed metrics and the
cross-run comparison.

## Why this looked so weird on the graph

The graph is visually strange because run 052's `c_effective_rank` starts at about `31`, while older
pre-sharp runs usually started around `9.47`. That start value is not a win. It is a mechanical
side effect of fixed orthogonal slot identities surviving into `c_t`.

At step 0, all videos have the same `c_t`, so:

```text
c_std_mean = 0
c_cross_video_cosine = 1
```

The only thing rank can see is the 32 fixed slots. As soon as training changes the slots to solve
reconstruction, that artificial slot-identity rank can shrink. Since no variance, SIGReg, or
covariance term pushes back, the optimizer is free to collapse the code toward a small set of shared
directions that decode well.

So the weird shape is not "a healthy rank curve going in reverse." It is:

```text
step 0: artificial slot-basis rank with no video information
later: low-dimensional reconstruction code with some video information, but still collapsed
```

The correct read is Q2 + Q3 together, not rank alone.

## Practical implications

1. **Do not transfer run 052's config into prediction.** The representation is not healthy enough.
   A full prediction run from this config would test `F_c` on a collapsed present code.

2. **The finished run strengthens the diagnosis rather than changing it.** The matched step-8000
   comparison already rejected the primary hypothesis, and the final step-14500 diagnostics moved
   further into the collapse pattern.

3. **The next clean apples-to-apples test is sharp slots with restored geometry pressure.** The
   question should be:

   ```text
   Does the sharp bottleneck improve the already-successful geometry recipe?
   ```

   not:

   ```text
   Can sharp attention replace the geometry recipe entirely?
   ```

4. **Add a present-recon honesty diagnostic.** Current `L_recon_present` alone can be fooled by a
   shared/template-like latent. Add diagnostics such as:

   - `L_recon_batchmean_c`: decode the batch-mean `c_t` for every video;
   - `L_recon_shuffled_c`: decode shuffled `c_t` against each video's `e_t`;
   - `L_recon_zero_c`: decode zero/common latent;
   - a "video-specific reconstruction gap": shuffled or batch-mean loss minus true loss.

   If run 052 is truly template-like, these ablations should be much closer to the true
   `L_recon_present` than they are in healthy video-specific runs.

5. **Add a between-video rank diagnostic.** Current pooled `c_effective_rank` can be inflated by
   slot identity because it pools `B * N_c` rows. A complementary metric should isolate video
   variation, for example effective rank of flattened per-video `c_t` after subtracting the
   per-slot batch mean, or rank of per-video slot means/residuals. Q2 already catches this, but a
   rank-like graph would prevent misreading the step-0 sharp-slot value.

## Clean-vs-controlled experiment clarification

The investigation-011 geometry sweep was not useless, but it answered a different question from run
052. It did not prove that reconstruction alone or the bottleneck architecture alone creates a good
representation. It showed that the present-only system can produce a healthy bottleneck when variance,
SIGReg, and sometimes covariance pressure are active, and it mapped which geometry recipes look
healthy.

That makes those runs positive controls and practical baselines, not pure architecture-attribution
evidence. Comparing run 052 against run 051 answers:

```text
Can sharp slots plus reconstruction-only replace the geometry recipe?
```

The answer is no. Running sharp slots with the same geometry as run 051 would answer a different,
controlled conditional question:

```text
Given a geometry recipe that already makes c_t healthy, does the sharp-slot architecture improve,
match, or degrade that practical recipe?
```

That comparison is not clean for the architecture-alone question. It is clean for the conditional
question because the geometry pressure is held fixed. The residual is still allowed to contain
architecture-geometry interactions, so it should not be oversold as universal proof that sharp slots
are good or bad by themselves.

For the pretraining plan, the implication is direct: run 052 should not be used as the bottleneck
pretrain. A usable pretrain either needs an already-healthy geometry-on checkpoint with compatible
architecture, or a new geometry-on pretrain using the current sharp-slot code.

## Bottom line

Run 052 is a clean negative result on the exact question it was designed to answer. It says:

```text
Sharp slot attention + reconstruction-only is not enough to make c_t healthy.
```

It does not say:

```text
The sharp-slot code is broken.
```

It also does not erase the investigation 011 result. The previous high-rank present-only runs were
high-rank because geometry losses were active. Run 052 removed those losses and immediately returned
to the old no-regularizer failure mode, just with a stronger decoder/reconstruction number and a
new slot-identity-shaped rank curve.
